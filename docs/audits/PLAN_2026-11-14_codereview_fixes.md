## P0 — критичные (приватность и корректность конфигурации)

### 2.1 Утечка приватных данных через артефакты GitHub Actions
- `.github/workflows/collect.yml`: состояние (vault + `state.db`) больше **не** сохраняется открытым текстом.
  Архив пакуется и шифруется `openssl aes-256-cbc -pbkdf2` ключом из секрета `KB_STATE_ENCRYPTION_KEY`;
  в публикуется только `kb-state.enc`.
- Если секрет не задан — состояние не сохраняется вовсе, job пишет предупреждение (безопасный дефолт).
- Явно задан `retention-days` (п. 4.3).
- Документация: `SECURITY.md`, `README.md` — «как включить шифрование состояния», рекомендация сделать репозиторий приватным.

### 2.2 Секреты в `GITHUB_ENV`
- Секреты передаются через `env:` конкретного шага, а не через `GITHUB_ENV`.
- `GITHUB_ENV` остаётся только для несекретных путей (`KB_DATA_DIR`, `KB_VAULT_PATH`, …).

### 3.2 Пустые секреты в CI ломают конфигурацию LLM
- `collect.yml`: секреты пробрасываются только при непустом значении.
- `kb_agent/config.py`: пустая (или из одних пробелов) переменная окружения трактуется как «не задано»
  и не перекрывает значение по умолчанию.

### 2.3 Реализация `local_processing_mode` и redaction
- Новый модуль `kb_agent/processing/privacy.py`: `Redactor` (поля/источники) + определение локальных провайдеров.
- `LLMClient`:
  - **guard**: при `local_processing_mode=True` и внешнем провайдере запрос не выполняется, возвращается ошибка;
  - **redaction**: чувствительные поля вырезаются из текста запроса (email, phone, url, токены и т.п.);
  - **источники**: `redact_sources` исключает контент источника из отправки внешнему LLM.
- `Pipeline`: элементы из исключённых источников помечаются `skipped` с причиной (контент не уходит наружу).
- `SearchEngine`: заметки из исключённых источников не попадают в контекст LLM-ответа.
- Тесты — на поведение, а не на чтение конфига.
