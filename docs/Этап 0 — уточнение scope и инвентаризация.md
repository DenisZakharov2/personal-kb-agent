# Этап 0 — уточнение scope и инвентаризация: зафиксированные решения

Проект: База знаний (personal-kb-agent)  
Репозиторий: https://github.com/DenisZakharov2  
Статус: только план и документация, код пакета `kb_agent/` ещё не написан. Этап 0 подготавливает фундамент перед началом разработки на Этапе 1.

---

## 1. Режим работы: локальный однопользовательский (подтверждён)

- Один пользователь, один Obsidian vault на локальной файловой системы.
- Состояние приложения — только один SQLite-файл (`data/state.db`) в локальном каталоге данных. Внешняя реляционная БД, векторная БД, брокер очередей и микросервисы не используются.
- Сбор и интеллектуальная обработка запускаются локально вручную или через системный cron.
- Внешние ИИ-агенты (Hermes, Cursor, ClaudeCode, OpenCode, OpenClaw, Kimi Claw) интегрируются через MCP-сервер `kb-agent mcp-serve` и CLI с флагом `--json`, а не через отдельные HTTP-адаптеры из Python.
- Формат знаний — Markdown с YAML frontmatter (Obsidian), конфигурация — только YAML/MD.

---

## 2. Источники MVP: Telegram + YouTube (2 источника)

**Выбрано для MVP:**
1. **Telegram** — публичные каналы `t.me/s/<channel>` (текст постов, дата, ссылка). Логика существующего `scripts/collect_telegram.py`.
2. **YouTube** — метаданные видео и автоматические субтитры через `yt-dlp` (без скачивания видео). Логика существующего `scripts/collect_youtube.py`.

**По пожеланиям:** поиск новых источников вне заданного списка в MVP не требуется. Источники выбирает человек (команды `sources add/remove/list/enable/disable` на Этапе 2). Остальные типы источников (сайты/RSS, arXiv, личные файлы, соцсети-плагины) откладываются на более поздние этапы.

---

## 3. LLM-провайдер для MVP: OpenAI

**Выбран один провайдер:** OpenAI (OpenAI-совместимый HTTP API), клиент `httpx`.  
Остальные провайдеры (Anthropic, Ollama, OpenRouter и прочие) подключаются только после проверки совместимости, не входит в MVP.

### Минимальный контракт `LLMClient`

```
LLMClient.complete(messages, *, model, temperature, max_tokens, response_format=None) -> LLMResponse
```

- `messages` — список сообщений `{role, content}`; исходный текст материала изолируется от системных инструкций (защита от промпт-инъекций).
- `LLMResponse` — `{text, model, prompt_tokens, completion_tokens, latency_ms, error}`.
- Для каждого вызова фиксируются: модель, параметры, версия промпта, ошибки, задержка, стоимость (если применимо).
- Структурированный ответ валидируется отдельной Pydantic-схемой под каждую задачу (суммаризация, отбор релевантности, ответ на вопрос и т.д.).
- Провайдер, модель и параметры фиксируются явно; автоматического «подбора» провайдера нет.

## 4. Судьба существующих скриптов `scripts/`

**Принцип:** один поток конвейера, не два параллельных.

Один поток: источник — SQLite-таблица `raw_queue` — Processing Layer (`kb_agent`) — заметки `.md` в vault + FTS5-индекс.  
Старый файловый конвейер (`_queue.jsonl`, `_done.txt`, `_trans_done.txt`, `_transcripts/`) выводится из активного конвейера. Запись в `_queue.jsonl` прекращается.

| Скрипт | Решение | Комментарий |
|---|---|---|
| `scripts/collect_telegram.py` | **Оставляется как референс и источник сырья; логика оборачивается** в `kb_agent/sources/telegram.py` на Этапе 2 | Старый скрипт больше не является частью активного конвейера. Новый путь пишет в SQLite `raw_queue`, а не в `_queue.jsonl` |
| `scripts/collect_youtube.py` | **Оставляется как референс; логика оборачивается** в `kb_agent/sources/youtube.py` на Этапе 2 | Команда `transcripts` (скачивание субтитров json3) переносится в источник YouTube. Кэширование и паузы между запросами сохраняются |
| `scripts/run.sh` | **Выводится из конвейера** (больше не используется) | Заменяется командой `kb-agent process` и записью в системный cron |

Физическое удаление старых скриптов не выполняется в Этапе 0. Решение о удалении/архивации фиксируется на Этапе 1. Рабочие файлы старого конвейера остаются в `.gitignore`.

## 5. Утверждённая схема данных

### 5.1. Источник (`source`) — `sources.yaml` (конфиг, единственный источник истины)

| Поле | Тип | Описание |
|---|---|---|
| `id` | строка | Устойчивый идентификатор источника (например, `tg_ragnarokzone`) |
| `type` | строка | `telegram` / `youtube` / `website` / `papers` / `personal` / `social` |
| `url` | строка | Канонический URL источника |
| `enabled` | булево | Включён ли источник для сбора |
| `last_checked` | дата-время | Время последней проверки источника |
| `last_updated` | дата-время | Время последнего изменения содержимого источника |

### 5.2. Элемент очереди (`raw_queue`) — SQLite

| Поле | Тип | Описание |
|---|---|---|
| `id` | целое, PK | Идентификатор элемента |
| `source_id` | строка | Ссылка на источник |
| `external_id` | строка | Внешний идентификатор элемента в источнике (message_id, video_id и т.п.) |
| `canonical_url` | строка | Канонический URL элемента |
| `title` | строка | Заголовок |
| `raw_text` | текст | Сырой текст материала |
| `raw_hash` | строка, уникальный | Хеш нормализованного содержимого (дедупликация) |
| `received_at` | дата-время | Время получения в очередь |
| `state` | строка | `new` / `processing` / `processed` / `skipped` / `failed` |
| `attempts` | целое | Число попыток обработки |
| `last_error` | текст | Текст последней ошибки |
| `next_retry_at` | дата-время | Время следующей попытки при `failed` |
| `skipped_reason` | текст | Причина пропуска при `skipped` |

Ограничение уникальности: `UNIQUE(source_id, external_id)` и `UNIQUE(raw_hash)`.

### 5.3. Заметка (`note`) — `.md` в vault + `notes_fts` (FTS5) в SQLite

| Поле | Тип | Описание |
|---|---|---|
| `note_id` | строка, PK | Устойчивый идентификатор заметки |
| `source_id` | строка | Идентификатор источника |
| `source_type` | строка | Тип источника (хранится в frontmatter) |
| `external_id` | строка | Внешний идентификатор элемента |
| `canonical_url` | строка | URL или путь к исходному материалу |
| `published_at` | дата-время | Дата публикации в источнике |
| `received_at` | дата-время | Дата получения в систему |
| `updated_at` | дата-время | Дата последнего обновления заметки |
| `previous_note_id` | строка | Ссылка на предыдущую версию заметки (актуализация) |
| `frontmatter_schema_version` | целое | Версия схемы frontmatter |
| `title` | строка | Заголовок заметки |
| `tags` | строка | Теги |
| `topic` | строка | Предметная область из профиля пользователя |

Авторитетная копия заметки — файл `.md` в vault; SQLite хранит метаданные и FTS5-индекс для поиска.

### 5.4. Связь заметок (`note_links`) — SQLite

| Поле | Описание |
|---|---|
| `source_note_id` | Идентификатор исходной заметки |
| `target_note_id` | Идентификатор целевой заметки |
| `link_type` | `references` / `contradicts` / `updates` / `extends` |

Ограничение: `PRIMARY KEY (source_note_id, target_note_id, link_type)`.

### 5.5. Обратная связь (`feedback`) — SQLite

| Поле | Описание |
|---|---|
| `note_id` | Идентификатор оценённой заметки |
| `score` | Оценка (1–5) |
| `comment` | Комментарий пользователя |
| `created_at` | Дата создания |

### 5.6. История промптов (`prompt_history`) — SQLite

| Поле | Описание |
|---|---|
| `prompt_name` | Имя промпта (например, `summarize`) |
| `version` | Версия промпта |
| `content` | Содержимое промпта |
| `is_active` | Является ли активной версией |
| `created_at` | Дата создания |
| `approved_by` | Кто одобрил |
| `reverted_from` | Версия, от которой произведён откат |

### 5.7. Профиль пользователя (`user_profile`) — `user_profile.yaml`

| Раздел | Содержимое |
|---|---|
| цели | Цели базы знаний (работа, учеба, саморазвитие, хобби) |
| задачи | Какие задачи БЗ должна решать |
| темы | Предметные области интересов |
| источники | Список подключённых источников (ссылки на `sources.yaml`) |
| частота | Частота сбора и напоминаний |
| система | Система работы (по умолчанию Obsidian) |
| ядро | Пути к существующим материалам для первичного импорта |

Примеры файлов: `config/sources.example.yaml`, `config/user_profile.example.yaml` (см. репозиторий). При развёртывании копируются в `data/sources.yaml` и `data/user_profile.yaml`.

## 6. Проверка файла LICENSE

- **Текст лицензии:** стандартный MIT License (соответствует тексту OSI MIT), корректный.
- **Правообладатель:** в файле указано только `Copyright (c) 2026`, имя правообладателя не указано. **Требуется дополнить**, например: `Copyright (c) 2026 Denis Zakharov (DenisZakharov2)`.
- **Совместимость сторонних зависимостей:**
  - Существующие скрипты: `requests` (Apache 2.0), `beautifulsoup4` (MIT), `yt-dlp` (общественное достояние / Unlicense, внешняя программа) — совместимы с MIT.
  - Планируемые на Этапе 1: `pydantic` (MIT), `typer` (MIT), `rich` (MIT), `httpx` (MIT), `pytest` (MIT), `ruff` (MIT) — совместимы с MIT.
  - `python-dotenv` не используется (чтение окружения через `pydantic-settings`, что не противоречит запрету).
- Вывод: LICENSE пригоден к использованию после добавления имени правообладателя.

## 7. Набор материалов и вопросов для проверки качества (Этапы 2–3)

Материалы — примерные заметки для проверочного набора (реальное содержимое подставляется на Этапах 2–3):

| # | Материал | Источник | Ожидаемое содержимое |
|---|---|---|---|
| 1 | Заметка про отчёт OpenAI | Telegram (`ragnarokzone`) | Сообщение о двух случаях ослабления контроля ИИ-агентами за собой |
| 2 | Заметка про проверку GPT-6 Astra | YouTube | Практическая проверка модели на реальных задачах: автомонтаж, лендинг, чат-бот |
| 3 | Заметка про автоматизацию | Сайт / RSS | Статья про автоматизацию процессов (n8n и аналоги) |
| 4 | Заметка про arXiv-статью | papers | Ссылка на статью и краткая аннотация |
| 5 | Личная заметка пользователя | personal | Собственные материалы человека |

### Типовые вопросы для проверки поиска и суммаризации

| # | Вопрос | Тип проверки | Ожидаемый результат |
|---|---|---|---|
| 1 | «Что сообщила OpenAI о случаях ослабления контроля ИИ-агентами за собой?» | Фактический поиск | Ответ со ссылкой на заметку 1 и цитатой |
| 2 | «В чём различие между автоматизацией в видео про GPT-6 Astra и подходом n8n?» | Сравнение источников | Ответ со ссылками на заметки 2 и 3 |
| 3 | «Какие темы повторяются в Telegram-каналах и на YouTube независимо друг от друга?» | Скрытая зависимость / инсайт | Указание на общие темы с ссылками на заметки-доказательства |
| 4 | «Что сказано в базе о квантовых вычислениях?» | Недостаток данных | Явный ответ «в базе недостаточно данных», без догадок |
| 5 | «агент ИИ ослабил контроль» | Русскоязычные словоформы / синонимы | Находит заметку 1 несмотря на иную формулировку |
| 6 | «GPT-6 Astra проверка» | Транслитерация / название | Находит заметку 2 |
| 7 | Изменение исходного материала в тестовом источнике | Актуализация | Система предлагает обновить связанную заметку с diff и резервной копией, а не перезаписывает молча |
| 8 | «Оцени эту заметку» + комментарий | Обратная связь | Оценка и комментарий сохраняются в `feedback` |

Критерии качества фиксируются на Этапах 3–5: релевантность топ-N, наличие ссылок на заметки и исходные материалы, поведение при недостатке данных, отсутствие выдуманных фактов.

## 8. Стек и ограничения (кратко)

**Используются:** Python 3.10+, Pydantic v2, Typer + Rich, httpx, SQLite (встроенный `sqlite3` с FTS5), pytest, ruff.  
**Не используются:** `python-dotenv`, `loguru`, `mypy`, `APScheduler`, `Jinja2`, `pytest-asyncio`, шесть HTTP-адаптеров агентов, микросервисы, внешняя БД, векторная БД, веб-интерфейс.  
**Конфиг:** только YAML/MD (`user_profile.yaml`, `sources.yaml`, промпты).  
**Состояние:** только SQLite.
