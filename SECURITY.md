## Сообщение об уязвимости

Если вы обнаружили уязвимость в безопасности, **не создавайте публичный Issue**.

Вместо этого отправьте отчет на email: **security@zakharov.dev** (или создайте [Private Vulnerability Report](https://github.com/DenisZakharov2/personal-kb-agent/security/advisories/new) на GitHub).

Включите в отчет:
- Описание уязвимости и её влияние
- Шаги для воспроизведения (PoC)
- Версию пакета / коммит
- Ваше окружение (ОС, Python версия)

Мы подтвердим получение в течение 48 часов и предоставим план исправления.

## Модель угроз и меры защиты

### Данные, отправляемые внешнему LLM

При использовании внешних провайдеров (OpenAI, Kimi, OpenRouter и др.) отправляются:
- Сырой текст постов/видео при суммаризации
- Фрагменты заметок (snippets) и метаданные при поисковых ответах
- API-ключ (в заголовке Authorization)

**Меры защиты:**
- Режим локальной обработки (`KB_LOCAL_PROCESSING_MODE=true`) — полностью отключает отправку наружу, работает только с локальным Ollama
- Редакция полей (`KB_REDACT_FIELDS`) — исключает чувствительные поля (email, phone, URL) из отправки
- Редакция источников (`KB_REDACT_SOURCES`) — исключает целые источники из отправки
- Приватные заметки/источники (`is_private=1`) — не возвращаются через MCP

### Цепочка недоверенного контента

- Контент из внешних источников (Telegram, YouTube) помечается как `untrusted_content`
- MCP-сервер **не имеет** инструмента подтверждения — модель не может применить изменения сама
- Write-инструменты MCP создают pending-запросы, применяемые только человеком через `kb-agent confirm <id>`
- Allowlist доменов для добавления источников (t.me, youtube.com, youtu.be)
- yt-dlp ограничен известными YouTube-доменами

### Локальное хранение

- Все заметки, состояние, профиль — в локальном SQLite (`data/state.db`) и файлах vault
- Никакие данные не отправляются на серверы разработчика
- Логирование локальное (файл `data/kb_agent.log`)

## Безопасность зависимостей

Зависимости проверяются через `pip-audit` в CI/CD pipeline. Для локальной проверки:

```bash
pip install pip-audit
pip-audit --desc
```

## Конфигурация безопасности

Рекомендуемые настройки для максимальной приватности:

```bash
# Полная локальность (требует Ollama)
export KB_LOCAL_PROCESSING_MODE=true
export KB_LLM_PROVIDER=ollama
export KB_OPENAI_BASE_URL=http://localhost:11434/v1

# Редакция чувствительных полей
export KB_REDACT_FIELDS="email,phone,canonical_url"

# Приватные источники (не отправляются в LLM)
export KB_REDACT_SOURCES="tg_private,yt_internal"
```

## Известные ограничения

1. **yt-dlp** выполняет сетевые запросы к YouTube — изоляция на уровне ОС/контейнера рекомендуется
2. **API-ключ** в логах — при отладке может попасть в логи, используйте `--log-level WARNING` в продакшене
3. **MCP stdio** — сервер имеет доступ к файловой системе пользователя (vault, БД)
