## [Unreleased]

### Исправлено
- **Приватность в CI:** состояние базы (vault + `state.db`) больше не публикуется открытым текстом
  в артефактах GitHub Actions — архив шифруется (`openssl aes-256-cbc -pbkdf2`) ключом из секрета
  `KB_STATE_ENCRYPTION_KEY`; без секрета состояние не сохраняется вовсе. Задан явный срок хранения
  артефакта (7 дней)
- **Секреты в CI:** секреты передаются через `env:` конкретного шага вместо `GITHUB_ENV`
  (больше не становятся постоянными переменными окружения для всех последующих шагов)
- **Пустые секреты в CI:** пустая переменная окружения больше не перекрывает значение по умолчанию
  (`load_config` трактует пустое значение как «не задано»)
- **`KB_LOCAL_PROCESSING_MODE` и redaction реально работают:** в локальном режиме запросы к внешнему
  LLM блокируются (раньше настройка только читалась); `KB_REDACT_FIELDS` вырезает чувствительные
  значения из запроса; `KB_REDACT_SOURCES` исключает контент источников из суммаризации и из
  контекста LLM-ответа. Добавлены поведенческие тесты
- **Двойной инкремент `attempts`:** счётчик попыток ведётся только в `claim_next`, из-за чего
  экспоненциальный backoff рос вдвое быстрее задуманного (1, 2, 4, 8 … минут)
- **Утечка соединений в MCP:** `StateManager`/`LLMClient` кэшируются на уровне процесса и
  закрываются при завершении сервера (раньше новое соединение создавалось на каждый вызов
  инструмента и никогда не закрывалось)
- **Контракт `kb_search`:** `maximum` лимита в JSON-схеме приведён к фактическому (20),
  а `total` теперь считается честным `COUNT` по FTS (добавлены поля `returned` и `has_more`)
- **Поиск дублей:** добавлена детерминированная сортировка и строгий критерий (общие теги **и**
  схожесть заголовков) — раньше одинаковые теги давали много ложных срабатываний
- **Фильтр спама в Telegram:** маркеры проверяются по границам слова («купить» больше не считается
  «купи», но «скидки»/«розыгрыши» распознаются по основе), причина пропуска сохраняется
  в `skipped_reason`, а отфильтрованный пост можно вернуть через `kb-agent retry <id>`
- **Предохранитель в конвейере:** при недоступном LLM очередь больше не «сгорает» целиком — после
  трёх подряд неудач обработка останавливается, а при открытом circuit breaker `LLMClient`
  текущий элемент возвращается в `new` без роста backoff, остальные остаются в `new`
- **`PROJECT_ROOT`:** корень проекта определяется по расположению `__file__`, а не по наличию
  чужого `pyproject.toml` в текущей директории
- **Мелкие правки:** корректное сообщение об отсутствии `yt-dlp` (extra `youtube` не существует),
  устойчивое извлечение JSON из ответа LLM, `yaml.safe_dump` вместо `yaml.dump`, явные скобки в
  `_make_snippet`, исправлены опечатки и артефакты генерации в комментариях

### Добавлено
- Модуль `kb_agent/processing/privacy.py` — политика приватности (локальный режим, redaction полей
  и источников) с набором тестов
- Функция `detect_spam()` в `kb_agent/utils/spam.py` — единый антиспам-фильтр возвращает причину
  срабатывания (пишется в `skipped_reason` очереди)
- Блокирующая проверка типов: `scripts/check_mypy_baseline.py` + `ci/mypy-baseline.txt`
  (CI падает при росте числа ошибок mypy; текущий долг снижен со 119 до 54 ошибок)
- Блокирующий `pip-audit` в CI (раньше проверка была декоративной из-за `|| true`).
  Аудит выполняется в изолированном окружении с зависимостями проекта
  (`scripts/audit_dependencies.sh`): предустановленные инструменты образа runner'а
  (пиновые `pip`/`setuptools`) не относятся к проекту и давали ложные срабатывания
- Исправлена уязвимая версия pytest в dev-зависимостях: `pytest>=8.0,<9` →
  `pytest>=9.0.3,<10` (PYSEC-2026-1845); версия согласована с `uv.lock`,
  рассинхрон которого появился в коммите `41e73ae`
- Проверка синхронности промптов `config/prompts` ↔ `kb_agent/resources/prompts`
  (`scripts/check_prompts_sync.py`)
- Все GitHub Actions закреплены по SHA; у всех workflow добавлен минимальный `permissions: contents: read`

### Изменено
- `AppConfig` предоставляет готовые пути (`db_file`, `profile_file`, `sources_file`, `log_file`,
  `vault_dir`) — меньше `Path | None` в коде и в проверках типов
- Отчёты аудита перенесены из корня репозитория в `docs/audits/`

## [0.2.0] - 2026-11-06

### Добавлено
- MCP-сервер с 12 инструментами (read + write через pending-подтверждение)
- Система версионирования промптов с откатом (self-improve)
- Обратная связь и метрики качества (feedback rate/tell/metrics)
- Режим локальной обработки (KB_LOCAL_PROCESSING_MODE)
- Редакция чувствительных полей/источников (KB_REDACT_FIELDS, KB_REDACT_SOURCES)
- Автоматическая генерация Каталог.md и Дайджест.md
- Полнотекстовый поиск через SQLite FTS5
- Сбор из Telegram и YouTube с дедупликацией
- Relevance Gate на основе пользовательского профиля
- Система миграций БД (schema_version)
- 297 тестов (pytest)

### Изменено
- Исправлена логика untrusted_content в MCP (внешний контент = untrusted)
- Исправлен CI workflow для автоматического сбора (восстановление state.db)
- Исправлены ошибки YouTube-сборщика (языки субтитров, raw_hash, mark_processed)
- Добавлена проверка TTL (expires_at) при подтверждении pending-изменений
- Исправлен приоритет загрузки .env файлов
- Исправлено несовпадение заголовков между Vault и SQLite FTS5
- Исправлен расчет score из FTS5 rank
- Расширен список стоп-слов для RelevanceGate
- Добавлена CI-проверка синхронизации config/ и kb_agent/resources/
- Исправлена разметка Markdown в README.md
- Добавлены недостающие переменные в .env.example
- yt-dlp перенесен в основные зависимости, убрана верхняя граница версии
- Удалена зависимость requests (заменена на httpx)
- Очищен корень репозитория (проектные черновики → docs/history/)
- Настроены GitHub Topics из keywords pyproject.toml

### Исправлено
- Подавление ошибок сборщиков (теперь пробрасываются для корректного exit code)
- Сбор старых постов вместо новых в Telegram
- Баги в генераторе каталога и VaultManager (None-safety, utf-8, atomic writes)
- Ложные срабатывания RelevanceGate из-за неполных стоп-слов
- Несовпадение типов промптов между prompts.py и search.py

## [0.1.0] - 2026-10-01
